## 1. ACME-F-001 — SSRF（高，money_ready）

**资产**：`https://api.demo-acme.example.com/api/v1/asset-preview?url=`

**漏洞描述**：`url` 参数由服务端直接请求且无协议/网段校验，可读取本地文件与内网服务，并通过组合验证证明可被利用为内网探测。

**证据链**（`poc-acme-001.py --demo` 可完整重放）：

1. 现象（3 包定性）：`file:///etc/hosts` 回显 → 服务端真实文件读取
2. 组合验证：`http://10.0.0.10/conf.json` 回显内网管理配置（`"内网管理网段": "10.0.0.0/8"`）→ 证明可做内网探测
3. 反事实 4 问：
   - (1) 换地址返回不同内容 → 非缓存，真请求 ✅
   - (2) 无认证可触发 → 未授权面 ✅
   - (3) 不可达地址 502 vs 可达 200 → 非误报 ✅
   - (4) 证伪反例：直连脚本重放仍成立，无法推翻 ✅

**PoC**：`python output/poc-acme-001.py --demo`

**修复建议**：服务端请求目标 URL 白名单 + 协议白名单（禁 file/dict/gopher）+ 内网网段拦截 + DNS rebinding 防护。

## 2. ACME-F-002 — 认证绕过 `..;/`（高）

**资产**：`https://admin.demo-acme.example.com/admin/dashboard`

**漏洞描述**：网关路径归一化与后端不一致，`/assets/..;/admin/dashboard` 在网关层命中静态资源放行规则，后端归一化后落到管理接口，**无任何凭据**直达管理后台订单总览。

**证据链**（`poc-acme-002.py --demo` 判别三连）：

- P1 直连 `/admin/dashboard` → **401**（鉴权确实存在）
- P2 `/assets/..;/admin/dashboard` 无 Cookie → **200** + 业务数据（`total_orders: 128`）
- P3 假资源 `/assets/..;/not-exist` → **404**（排除网关统一放行）

**反事实补强**：去掉 `..;/` 即 401 → 确认是归一化差异而非接口本身无鉴权；全程未携带凭据 → 未授权成立。

**PoC**：`python output/poc-acme-002.py --demo`

**修复建议**：网关与后端统一路径归一化规则（RFC 3986 标准实现），管理接口禁止经静态资源前缀可达。

## 3. ACME-F-003 — IDOR 越权读订单（中）

**资产**：`https://api.demo-acme.example.com/api/v1/orders/{id}`

**漏洞描述**：订单详情接口仅校验登录态、未校验归属，替换订单 id 可读取他人订单（含金额、地址哈希）。仅 GET 读取，未批量。

**证据链**（`poc-acme-003.py --demo`）：

- 基线：A 会话读自己订单 ORD-2026-08121 → owner=account-a
- 反证：替换 ORD-2026-08123 → owner=**account-b**（非 A 下单记录）→ 归属未校验
- 反事实：(2) 无 Cookie 401 ✅ (3) 不存在订单 404 ✅ (4) 证伪反例无法推翻 ✅

**PoC**：`python output/poc-acme-003.py --demo`

**修复建议**：对象级鉴权（按 owner 过滤），接口层加归属断言。
