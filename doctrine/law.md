# 法律红线 (全场景必读，不可妥协)

> **适用范围**：所有 mode (src / pentest / redteam) 共享。
> **定位**：本文件是唯一硬约束来源。其他 doctrine 谈质量/效率，这里谈法律和职业生涯。
> **最高原则**：不确定算不算违法 → 算。先停，问用户，再做。

---

## 4 条铁律 (强制)

### 1. 不破坏 (禁止不可逆操作)
不做任何破坏性操作，包括但不限于：`rm -rf`、`DROP TABLE`、无 `WHERE` 的 `DELETE`、`fork bomb`、`dd` 写盘等。
- **工程拦截**：系统会通过正则主动拦截已知灾难模式（见 `.claude/settings.json` 和 `danger-guard.sh`）。
- **AI 自律**：工程层无法覆盖所有变体，超出清单的破坏性操作，必须依赖 AI 自律 + `_PENDING.md` 请示 + `timeline.md` 留痕。

### 2. 不影响业务 (保护真实数据与资金)
严禁修改/删除真实业务数据。越权测试仅限 `GET` 读取（IDOR fuzz / 参数遍历 / 目录爆破均视为只读，一律放行）。
- **写操作豁免 (必须同时满足)**：
  1. 使用自己注册的小号（或合法获取的测试账号，见铁律4豁免）。
  2. 使用无害 payload (如 `test_vuln`，严禁 Webshell)。
  3. 测完立即清理。
  4. 报告末尾必带 `[清理动作]` 段。
- **资金类操作**：支付/下单/转账/退款/提现/优惠券核销，最终提交前**必须拦截**。测试需用自己账号 + 最小金额 (0.01元) + 立即退款。涉及外发骚扰 (短信/邮件)，接收端只能是自己控制的账号。
- **业务语义拦截 (L2)**：系统根据 HTTP Method × Path 动作 × Body 字段角色判定（如区分“登录”与“改密”），而非单纯关键词匹配。拦截改密、删数据、资金提交、SQL写等操作。

### 3. 不下载敏感数据 (禁止批量获取)
- **不 Dump 数据库**：发现 SQLi 仅取 1-2 行 Proof 或 Count，绝不拖库。
- **不下载源代码**：发现目录穿越可读 `.java/.py/.zip`，仅截图证明，绝不批量下载。
- **不批量拉取 PII**：用户表/订单表仅取 Count + 1 条脱敏样例，绝不批量导出或打包。
- **边界**：越权 GET 读取单条/少量记录证明可访问 → OK；批量爬取/打包下载 → 越界违法。

### 4. 重武器先请示 (控制破坏半径)
扫描分为“决策动作”和“执行动作”，严禁误判导致错失高 ROI 漏洞或引发事故。

#### 4.0 授权分级（L0-L3 — 按包数+操作类型判定，不按工具名）

| 级 | 内容 | 授权方式 | 判定依据 |
|---|---|---|---|
| **L0** | 只读 GET 探测（IDOR/参数遍历/目录爆破/单包探针/采样 ≤5 条） | **默认授权** | 不落库、不写、GET-only |
| **L1** | 1 包级口令/默认凭据/签名验证（1 包，命中即停） | **批量预授权**：用户一次"全批 L1"覆盖当日可批清单，逐条记录 `approval_queue` | 包数=1 + 操作类型=验证（非利用链） |
| **L2** | 注册类（真实手机号/账号创建/留资写库） | **单次批准** | 需真实个人信息/写操作 |
| **L3** | 重武器（sqlmap/nuclei 字典/上传 PoC/RCE/反序列化/完整攻击链如 Bleichenbacher） | **单次批准**（沿用 §4.1） | 按工具名+攻击链 |

**判定口径**：默认凭据 1 包验证（如 `Harbor12345`、RuoYi admin/admin）、单包 oracle 分叉确认（如 Bleichenbacher padding oracle）→ **L1 预授权**；完整攻击链利用（如完整 Bleichenbacher 解密）→ L3。默认凭据 1 次尝试（原 §4.1 执行细则）归入 L1，不再走单条请示。

**L1 判别包指纹确认前置（law.md §4.0，必填）**：每条 L1 判别包进 `approval_queue` 时**必须携带"目标指纹确认记录"**（lifecycle.yaml 条目加 `fingerprint` 字段，1 包内确认）：
- 内容：N-day 识别器输出 / 登录页特征 / 认证面形态（banner/响应头/框架特征/前端 JS 提示），一句话写明"目标到底是什么"
- 反例（判别包按"印象中的目标"设计失败的教训）：指纹确认必须基于实际响应特征（banner / 登录接口形态 / 认证机制），不能按框架名假设——如 Harbor db_auth 下 Basic auth 在 REST API 不生效（匿名 /projects 200、basic+口令 /users 401 无判别性），判别包必须打真实登录端点；Vue SPA 全路径 200 fallback 时默认口令验证不适用，须先从前端 JS 找真实登录 API
- **验收**：下一批 L1 项全部带指纹确认记录才进队列；缺指纹 → 不生成判别包，先做 1-2 包指纹确认（L0 只读，默认授权）。

#### 4.1 重武器 (必须请示，任一中招即停)
- **工具类**：`sqlmap` (任何参数)、`nuclei` (非单模板)、`dirbuster/ffuf` (字典>1000/多host/请求>5000)、`nmap` (全端口/全网段)、`msfconsole`。
- **PoC 类**：RCE、反序列化 (Shiro/Fastjson/Struts/Log4j)、文件上传。
- **Fuzz 类**：任何 POST/PUT/DELETE 的写参数 fuzz。

**执行细则 (1次承诺)**：获批后，payload 命中即停，不换入口/不换变体加发。
- 默认凭据：1 次尝试，命中即停（**L1 预授权**，见 §4.0；不属本条重武器请示）。
- RCE/反序列化：1 次发包，载荷限 `whoami/id/echo`，命中即停（L3）。
- **字典暴破真账号：0 次 (死线)**。指已知真实账号名，反复使用字典尝试密码（如已知 `admin` 试 100 个密码）。
- 扩战果 (更深 payload/容器逃逸/横向)：必须写 `_PENDING.md` 重新拍板。

#### 4.2 定向扫描 (L0 默认授权，timeline.md 留痕)
**必须全部满足**（缺一即退化为 4.1 重武器 / L3）：
1. 单 host (scope 内白名单)。
2. 字典 ≤ 200 entries。
3. 仅 GET 请求。
4. 字典基于已知锚点生成（非通用大字典）：JS 提取路径、已发现接口同前缀枚举、业务功能路径模式、框架默认路径 (Spring Boot/Swagger 等)。
> *免请示原因：法律性质等同于 IDOR/参数遍历（只读），属 L0 默认授权（§4.0）。避免 AI 将“业务路径手敲”误判为重武器而关停，导致漏报。*

#### 4.3 无注册站点获取测试账号 (豁免条款)
对于无注册入口的站点，必须获取账号才能测试业务逻辑。以下方式**不受“字典暴破真账号 0 次”限制**，SRC 准许：
- **弱口令爆破**：对登录接口使用字典（需走 4.1 重武器请示），命中即停，1 组账号足够。
- **信息泄露获取**：从已发现的泄露源 (.git/备份文件/API返回/配置文件) 获取凭据，仅取 1 组。
- **密码重置漏洞**：利用重置流程缺陷 (如 token 可预测/验证码回传) 获取账号控制权。
> **约束**：获取后仅用于本次测试；不修改该账号真实业务数据；报告中必须提交测试账号+获取方式+漏洞详情便于复现；报告末尾说明“测试完成，账号交还 SRC/甲方处理”。

#### 4.4 请示协议 (批量化，反请示风暴)
- 同 target 同攻击面的同质重武器，合并为一条请示。
- 写入 `targets/<>/_PENDING.md`，设定 30/60min 默认动作（不打/切下一面）。
- 用户回复“打”之前绝不执行，打完写 `[执行总结]` 留痕。
- **职责分界（双轨）**：发包 / 重武器授权 → `_PENDING.md`；战略 / 投递 / 材料等决策类 → `_STATE.md` “待决问题”段。勿混用，避免授权类请示被当成决策类搁置。
- **每日可批清单 (L1 批量预授权)**：会话开始时跑 `python tools/findings-lint.py targets/<t> --lifecycle --gen` 读 `targets/<t>/output/lifecycle-views/approval-queue.md`；用户回”批 1/3/5”或”全批 L1”即完成 L1 批量预授权（逐条在 lifecycle.yaml `approval_queue` 置 `approved: true` + `approved_at` 留痕）；L2/L3 项仍逐条请示。

## 工程层硬拦截说明

详见 `.claude/settings.json` permissions.deny + `tools/danger-guard.sh` + `tools/lib/business_impact.py`：
- **L1 灾难模式**：`rm -rf` / `DROP TABLE` / `jndi:` / `ysoserial` / 反弹 shell / WebShell / multipart 危险后缀等。
- **L2 业务破坏语义**：按 HTTP method × path 动作 × body 字段角色判定（改密/删数据/资金提交/SQL写）。
- **授权逃生口**：用户确认后，临时设置 `SRCOOP_DANGER_ALLOW=1` 再执行，并在 `timeline.md` 留痕。
