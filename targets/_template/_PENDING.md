# 待用户拍板队列(异步请示,v3 新增)

> 所有 L2 战略请示 / 重武器请示 / 候选项倒计时挂这里。
> **关键改动**:每条请示必须带「30 分钟默认动作」+「60 分钟默认动作」,**超时不阻塞,继续工作但默认偏保守**。
>
> 详见 `doctrine/law.md` → 重武器先请示

## 默认动作分级速查表

| 类型 | 30 分钟超时 | 60 分钟超时 |
|---|---|---|
| 重武器(sqlmap/RCE) | 不打,保留 cURL 状态;低强度手工探索 | 不打,标 [候选] 留档,切下一面 |
| 默认凭据(单次试) | 不试,跳过 | 跳过 |
| 战略(死磕 vs 切) | **继续低强度探索**(GET / 1RPS / ≤5 包) | 切并写为何切的复盘 |
| 候选项倒计时 | 自动证伪试探(1 包) | 降级 [phenomenon] 不删 |
| 灰度报告 (tentative) | 置信 ≥0.7 直投;否则 draft 等 | 同上,无变化 |

## 队列模板(新增请示时复制)

### A. 单点请示(默认)

```
## P-XXX (YYYY-MM-DD HH:MM) — <类型> 请示
- 类型: <重武器 / 默认凭据 / 战略 / 候选倒计时 / 灰度>
- 目标: <资产 / 端点 / 决策点>
- Payload (重武器才填):
  ```bash
  curl ...
  ```
- 30 分钟默认: <从分级表抄>
- 60 分钟默认: <从分级表抄>
- 提交时间: <epoch 或 ISO>
- 状态: ⏳ 等待中 / ✅ 已回复(打) / ❌ 已回复(不打) / ⌛ 30min默认触发 / ⌛⌛ 60min默认触发
```

### B. 批量请示(v3.5 新增,反请示风暴)

> 适用条件:**同 target 同攻击面下的同质重武器**(都是注入类 / 都是路径爆破类 / 都是反序列化类)。
> 获批一次覆盖整组,避免用户被高频请示弄麻木。

```
## P-XXX-BATCH (YYYY-MM-DD HH:MM) — 重武器批量请示
- 类型: 同质重武器组
- 攻击面: <例:订单子系统的 SQL 注入测试>
- 武器组:
  - sqlmap --risk=2 --level=3 (针对 /api/v1/orders/{id}, /api/v1/orders/search)
  - 手工时差盲注 payload (针对同上)
- 共同特征: <都不动数据 / 都只读 GET / 都在工作日时段>
- 影响估算: <预计 30 包 / 单包响应时间 ~3s / 总耗时 < 2 分钟>
- 退路: <发现 WAF 升级或异常告警 → 立即停>
- 30 分钟默认: 不打整组,标 [候选] 留档
- 60 分钟默认: 切下一攻击面,本组归 phenomenon
- 状态: ⏳ 等待中
```
